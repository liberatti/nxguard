# Diretrizes de Internacionalização (i18n)

## 1. Diretrizes Gerais

- **Zero Hardcode:** Nenhuma string visível ao usuário, atributo `aria-label`, `placeholder` ou mensagem de erro deve ser escrita diretamente no código.
- **Idioma Padrão (Fallback):** `en-US`.
- **Convenção de Chaves:** Formato `SCREAMING_SNAKE_CASE` hierárquico:
  ```text
  MODULO.FUNCIONALIDADE.ELEMENTO_OU_ESTADO
  Exemplo: AUTH.LOGIN.BUTTON_SUBMIT
  ```
- **Arquivos de Tradução:** Armazenados em `public/i18n/{lang}.json` (ou `src/assets/i18n/{lang}.json`). Mantenha as chaves sincronizadas entre todos os arquivos de idioma.

---

## 2. Frontend (Angular + Material)

- **Biblioteca:** `@ngx-translate/core`.

### Templates (HTML)
- Use preferencialmente a diretiva `translate` para elementos estáticos (evita reavaliação contínua de pipes em change detection) ou o pipe `translate`:
  ```html
  <!-- Diretiva (recomendado para textos estáticos) -->
  <h1 translate="AUTH.LOGIN.TITLE"></h1>

  <!-- Pipe (com interpolação ou em atributos) -->
  <p>{{ 'PROJECTS.OVERVIEW.TOTAL_COUNT' | translate:{ count: total } }}</p>
  <input matInput [placeholder]="'FORMS.PLACEHOLDERS.EMAIL' | translate" />
  ```

### Lógica (TypeScript)
- Evite `translate.instant()` se o componente puder carregar antes do arquivo de idioma ser baixado.
- Use `translate.stream()` ou signals/observables para textos reativos e notificações imperativas:
  ```typescript
  // SnackBar / Notificações
  this.translate.stream('NOTIFICATIONS.SUCCESS_SAVE').subscribe(message => {
    this.snackBar.open(message, undefined, { duration: 3000 });
  });
  ```

### Angular Material Internals
- Componentes internos do Material (paginador, datepicker, acessibilidade) devem ter seus adaptadores internacionalizados via Dependency Injection:
  ```typescript
  // Exemplo: Customizar MatPaginatorIntl para usar chaves do @ngx-translate
  providers: [
    { provide: MatPaginatorIntl, useClass: CustomMatPaginatorIntl }
  ]
  ```

### Formatação de Dados (Datas, Moedas e Números)
- Não use `@ngx-translate` para formatar números ou datas.
- Utilize os pipes nativos do Angular (`date`, `currency`, `number`) sincronizando o locale da aplicação via `LOCALE_ID` ou carregando dinamicamente os pacotes `@angular/common/locales`.

---

## 3. Anti-Padrões (O Que Evitar)

- **Concatenação de Strings:** Nunca construa frases somando strings traduzidas (`'HELLO' | translate + ' ' + userName`). Use parâmetros de interpolação (`{{ 'HELLO_USER' | translate:{ name: userName } }}`).
- **Pluralização Manual:** Não use condicionais (`*ngIf="count === 1"`) para tratar singular/plural no template. Utilize as capacidades de interpolação da biblioteca.
- **Tradução Tardia em Toasts/Dialogs:** Nunca envie strings hardcoded do backend para serem exibidas diretamente na UI. O backend deve retornar códigos de erro (ex.: `ERR_USER_NOT_FOUND`) e o frontend mapeia para a chave i18n correspondente.
